# Bun.ant.CellSegmenter: a JavaScript replacement

Status: **implemented and verified** against the native class (Claude Code
2.1.302 and 2.1.319). Code is in `bun-ant/`; tools are in `tools/`.

## Why

Interactive `claude` on FreeBSD hung before it drew anything. Claude Code's
terminal renderer needs `Bun.ant.CellSegmenter`, a native class in
Anthropic's private build of Bun (`@anthropic-ai/bun-internal`). Stock Bun
does not have it. The renderer threw inside a React render, React swallowed
the error under `<Suspense fallback={null}>`, and the process waited forever
on a screen that was never drawn.

The class is not published anywhere: not in upstream Bun, not on npm, not in
any public Anthropic repository. The only copy is machine code inside
Anthropic's Linux runtime, so we wrote our own.

`CellSegmenter` is the only part of `Bun.ant` Claude cannot do without.
Every other `Bun.ant` call (`posixFsAt`, `getPeerPid`, `getPeerUid`,
`loginTty`, `ttyName`, `setDumpable`, `memoryPressureLevel`, the Windows
ones) is feature-checked or wrapped in `try`/`catch`.

## How it is wired in

`regraft.js` adds four modules under `/$bunfs/root/freebsd/` to every
converted binary: `cellsegmenter.js`, `clusters.js`, `fused-data.js`, and a
generated `prelude.js`. The prelude becomes the entry point. It defines
`Bun.ant.CellSegmenter` only if the runtime lacks it, then imports Claude
Code's original entry. None of Claude's own modules change.

## How it was made exact

`tools/oracle.py` grafts any JavaScript onto Anthropic's Linux `claude`,
whose runtime has the real class, so test programs run the native and
JavaScript implementations side by side in one process on Linux.
`tools/cellseg-fuzz.js` is the differential test built that way. On 12
seeds it ran about 3 million `segment` calls, 1.8 million paints and 600,000
`setCell` calls with no differences. That covered all four pools, every
screen cell, damage ranges and return values, wide characters at the edge
and negative columns. Two deliberately planted bugs were each caught within
a few hundred calls.

Separately, every code point was checked in eight clustering contexts. And
Claude's own calls while drawing the first screen on FreeBSD (72 `segment`,
47 `paint`) were recorded and replayed against the native class: identical.

## The contract, as implemented

### Clustering and width

- Grapheme breaking is Bun v1.4.4's uucode algorithm
  (`src/jsc/bindings/stringWidth.cpp`, MIT), with its per-code-point table
  (`stringWidthTables.h`, Unicode 17). `fused-data.js` is that table,
  generated by `tools/gen-fused-data.py`.
- Anthropic's runtime differs from upstream Bun in two places:
  - C0/C1 controls end a cluster and are dropped.
  - VS16 widens an emoji base to 2, and the rest of the cluster still adds
    its width. VS15, and VS16 on a non-emoji base, leave the plain sum.
- Lone surrogates are skipped without ending a cluster. Escape sequences are
  transparent too, so a mark after `ESC[31m` joins the cluster before it.
- Zero-width clusters are dropped. A tab is its own cell (width 0, flag
  256). Code points in `substitute` become U+FFFD (width 1, flag 512).

### Escape sequences

- The grammar is Bun's `consumeANSI` (`ANSIHelpers.h`): CSI, OSC and the
  ST-terminated strings (DCS/SOS/PM/APC, 7-bit and C1 forms). ESC restarts a
  sequence, CAN/SUB abort one, and an unterminated string swallows the rest.
- OSC 8 sets the link target (`8;params;uri`; an empty uri closes the link).
  Other OSC and non-SGR CSI are ignored.

### SGR (styles)

- Parameters may contain only digits, `;` and `:`; otherwise the sequence is
  ignored. Any `:`, or any value over 255, keeps the whole sequence as one
  verbatim code. Otherwise the sequence splits into codes, with `38/48/58`
  joining their `5;n` or `2;r;g;b` arguments. Leading zeros are dropped and
  an empty parameter means 0.
- Close codes follow ansi-styles (`1,2→22`, `3,20→23`, `30-38,90-97→39`, and
  so on; unknown codes close with `0`).
- `0` clears the style. A close code removes every entry it closes. A new
  code replaces entries in its slot; slots are per attribute, with fg, bg,
  blink 5/6, super/subscript 73/74 and all unknown codes each sharing one.
  The new code goes to the end. An identical plain or extended code that is
  already present changes nothing; an identical verbatim code moves to the
  end.
- A cluster takes the style and link in effect where it *started*. A style
  enters `sgrKeys` when a cluster starts under it. A link enters `uris` as
  soon as it is parsed. A new run starts when (style, link) changes.

### paint and setCell

- On screen, a cluster of width w is written as a head (`word | wide`), one
  plain tail `[spacer, spacerTail]`, then styled tails for any further
  columns. One that does not fit (`col + w > width`) becomes a single
  spacer head and advances 1. Off screen to the left, nothing is written to
  column 0. Past the right edge every cell advances 1 and a tab advances 0.
- On screen, a tab goes to the next stop (C remainder for negative columns),
  capped at the edge, and clears the cells it skips.
- Every write repairs the wide pairs it breaks: replacing a tail clears its
  head, unless the new cell is itself a tail; replacing a head clears its
  tail.
- `paint` returns `max(col, 0) + 2^20·damageStart + 2^36·damageEnd`, with
  `0xFFFF-0` meaning no damage. `setCell` writes the word verbatim, adds a
  tail for a wide word when there is room, and returns `x + 1` plus damage.

## Known gaps

- **Bidi reordering** (`reorder = true`) is not implemented. Claude asks for
  it only in Windows Terminal and VS Code terminals (`WT_SESSION`,
  `TERM_PROGRAM=vscode`), and it only changes right-to-left text. In those
  terminals, Hebrew or Arabic shows in logical order.
- **Pool contents after an overflow.** When the output arrays are too small
  the native class stops interning part-way; ours interns everything it
  sees. Claude always retries with larger arrays, so the only effect is
  extra, unused pool entries.
- **Speed.** About 9 times slower than native (24 µs against 2.6 µs for a
  238-character styled line). A full 50-line screen costs about 1 ms, and
  Claude only re-segments lines that changed.
- **Outside CellSegmenter:** on the first screen, one run of reset codes
  comes out as `ESC[39m ESC[49m` where Linux emits `ESC[49m ESC[39m`. The
  terminal result is identical. The cause is some other difference between
  stock Bun and Anthropic's runtime, not this class.

## Re-checking a new Claude release

```sh
python3 tools/oracle.py <linux-claude> /tmp/fuzz tools/cellseg-fuzz.js \
    bun-ant/cellsegmenter.js bun-ant/clusters.js bun-ant/fused-data.js
for s in 1 2 3 4; do SEED=$s N=50000 /tmp/fuzz | tail -1; done
```

Any `failures` above 0 means the native class changed and the replacement
needs another look.
